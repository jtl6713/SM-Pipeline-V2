# Supabase migration — current status

Airtable is still the write source of truth for ideas, settings, slide patches, and the other skip paths. The half-hour Airtable copy is stopped while `STUDIO_WRITE_SOURCE=supabase`. Held-reschedule note readback reads Supabase when `STUDIO_WRITE_SOURCE=supabase`. Strict MAE occupancy reads Supabase when `STUDIO_WRITE_SOURCE=supabase` and does not walk Airtable. Stale Ready for Review, phantom rerender, live-failed publish, TikTok TTD0, native-photo review strands, and Instagram carousel heal candidate lists read Supabase when `STUDIO_WRITE_SOURCE=supabase` and do not list Airtable. TikTok draft reconcile (TTD0/1/2/3) and the light TTD2 processing poll also list Supabase when `STUDIO_WRITE_SOURCE=supabase` and do not list Airtable. Facebook rate-limit recovery and failed-status candidate lists read Supabase when `STUDIO_WRITE_SOURCE=supabase` and do not list Airtable. Instagram stale-upload candidate pages read Supabase when `STUDIO_WRITE_SOURCE=supabase`. The confirmation reread and the recovery ledger read Supabase when `STUDIO_WRITE_SOURCE=supabase`. Carousel slide reads for the verify-race heal and the carousel build use Supabase when `STUDIO_WRITE_SOURCE=supabase`. Plan occupancy reads the Supabase Production Request Output schedule. Slide patches stay on the Airtable export. Record deletion is not started. Airtable is a frozen archive: a successful Supabase commit is not exported. Phase 6 updates and creates commit to Supabase first when `STUDIO_PHASE6_WRITE_SOURCE=supabase` (`deploy/enable-studio-phase6-write-source.txt`). A successful Airtable create still returns Airtable's `rec` id. A failed Airtable create keeps the Supabase row. A Production Request create without an id and status, or a Media Asset create without a name, still requires Airtable. Platform Output and Content Item updates and creates commit to Supabase first, with Airtable as the legacy export (`STUDIO_WRITE_SOURCE=supabase`, enabled by `deploy/enable-studio-write-sor.txt`). A successful Output or Content create still returns Airtable's `rec` id. A failed Airtable create keeps the Supabase row. Google Drive is still the media authority. The isolated Studio project is the one named in [phase 3](./phase3/README.md). Do not use the tasks-api Supabase project.

The original roadmap in the [Phase 1 assessment](./phase1/SM_Pipeline_V2_Airtable_to_Supabase_Phase_1_Assessment.md) numbered a full write cutover as Phase 5 and Production Requests / media / cron as Phase 6. Production diverged: Phase 5 shipped Airtable-first write-through, and the list reads were restored one flag at a time after a global `STUDIO_READ_SOURCE=supabase` setting saturated the Postgres pool on Home polls. `studioReadSource()` stays hard-coded to `airtable` so that global flag cannot turn Home, Content, or Factory back on.

## What is still Airtable

- Creates outside Platform Outputs, Content Items, Production Requests, Media Assets, and the transfer queue. Those tables commit to Supabase first when their write flag is `supabase`. A successful Supabase commit keeps the minted `rec` id and does not update Airtable. A Phase 6 create without its insert identity still requires Airtable.
- Schedule/approve MAE verify reads the Supabase slot when `STUDIO_WRITE_SOURCE=supabase` (`maeSupabaseVerify`). A successful Supabase commit is enough for that verify. Held-reschedule note readback reads that Supabase row. Strict MAE occupancy reads Supabase and does not walk Airtable. Stale Ready for Review, phantom rerender, live-failed publish, TikTok TTD0, native-photo review strands, and Instagram carousel candidate lists read Supabase. Facebook rate-limit recovery and failed-status candidate lists read Supabase. Instagram stale-upload candidate pages read Supabase. The confirmation reread and the recovery ledger read Supabase when `STUDIO_WRITE_SOURCE=supabase`. The verify-race heal and the carousel build read carousel slides from Supabase. Plan occupancy reads the Supabase schedule copy. Slide patches stay on the Airtable export. Render heal candidate lists read the Supabase clip copy when `STUDIO_WRITE_SOURCE=supabase`. The creative-master registry is read from the Supabase content row. The review-media patch and render repair patches stay on the Airtable export. Render admission, the long-rendering heal, the Instagram stale confirmation and ledger readback, the carousel poll-failure slide read, the Quality Agent home census, and the best-effort calendar cache read Supabase when `STUDIO_WRITE_SOURCE=supabase`. Desk inventory output sweeps, the Quality Agent recovered-ledger scan, and render-queue active checks outside admission read Supabase when \STUDIO_WRITE_SOURCE=supabase\. An empty recovery copy still reads the Airtable ledger so recovered counts stay. Desk inventory request lists and the private-Drive watermark candidate list read Supabase. TikTok draft reconcile and the light TTD2 processing poll list Supabase. The half-hour copy stores reconciled recovery events. The other heals still list Airtable.
- Production Request, media metadata, and transfer-queue updates and creates commit to Supabase first when `STUDIO_PHASE6_WRITE_SOURCE=supabase` (`deploy/enable-studio-phase6-write-source.txt`). Confirm `phase6_writes=supabase_sor_legacy_export` on the next read-only gate.
- Pipeline-runner Output and Content lists use snapshotted Airtable views whose filters are stored columns (R5, R2B, C8, C9, AP0, and TTD3) and substring `FIND` on a text field when `STUDIO_RUNNER_OUTPUT_READ_SOURCE` or `STUDIO_RUNNER_CONTENT_READ_SOURCE` is `supabase`. Views that depend on an Airtable formula field, `OR` of a link lookup, and `FIND` inside a JSON column stay on Airtable. Unmarked rows and an empty match still fall back to Airtable.
- The half-hour Airtable copy is stopped while `STUDIO_WRITE_SOURCE=supabase`. Existing rows stay. When `STUDIO_WRITE_SOURCE=supabase`, an existing Platform Output keeps its Studio-owned schedule and approval columns. When `STUDIO_PHASE6_WRITE_SOURCE=supabase`, an existing Production Request, Media Asset, or transfer-queue row is not overwritten; a missing create is still inserted. The cron does not write Supabase back to Airtable.
- `STUDIO_HOME_PROFILE_SUMMARY_READS`. That is a separate Durable Object summary, and this cutover did not turn it on.
